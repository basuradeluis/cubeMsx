1. Reducir cálculos redundantes

Problema: Las líneas 480-530 calculan SIN(G) y COS(G) para cada arista, pero G solo cambia cuando el usuario pulsa una tecla.
Solución: Calcula S=SIN(G) y O=COS(G) una sola vez antes del bucle FOR I=0 TO 11 (por ejemplo, justo después de la línea 380).

Solución: Si la pantalla no cambia de tamaño, puedes precalcular los factores de escalado (ej: 256/2, 192/2) y usarlos directamente.

3. Usar arrays para almacenar puntos rotados

Solución: Crea un array temporal (ej: PR(8,2)) donde guardes los puntos ya rotados y proyectados antes de dibujar las líneas. Así, cada punto se calcula solo una vez por frame.

4. Evitar recalcular TIME innecesariamente

Problema: TIME se usa para medir el tiempo entre frames, pero no se usa para nada más.
Solución: Si no necesitas medir el FPS, elimina las líneas 60 y 660.

5. Optimizar el bucle de dibujo

Problema: El bucle FOR I=0 TO 11 dibuja todas las aristas, pero algunas pueden estar ocultas (ej: las de atrás).
Solución: Implementa un back-face culling simple: si el promedio de las coordenadas Z de los dos puntos de una arista es negativo, no la dibujes (está "detrás" del observador).

8. Evitar GOTO innecesarios
